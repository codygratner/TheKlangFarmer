# Architectural Plan: ToadTracker Core Migration
**Goal**: Transplant the robust, data-driven architecture, test harnesses, and audio-thread guardrails from *The Klang Farmer* to the `ToadTracker` repository to prevent duplicate effort and enforce real-time safety.
**Priority**: Super Low (Targeted for Post-v1.0 of The Klang Farmer).

---

## Phase 1: Architectural Guardrails & Invariants
*ToadTracker is designed to be cross-platform (SteamDeck, ESP32, Raspberry Pi, Desktop/JUCE). The core C++20 engine must remain completely allocation-free.*

1. **Migrate `GEMINI.md` Audio Invariants**:
   - Copy the strict audio-thread invariants (Zero Allocations, Zero Locks, Zero Blocking I/O) from `TheKlangFarmer/GEMINI.md` to `ToadTracker/GEMINI.md`.
2. **Port `audiothread-guard` Skill**:
   - Transfer the `audiothread-guard` and `build-validate` skills to ToadTracker to mechanically enforce DSP stability on every build.
3. **Upgrade `FastMath.h`**:
   - Replace ToadTracker's existing `core/include/toad/fast_math.h` with `TbdAudio::FastMath` from The Klang Farmer. This brings heavily optimized, vectorized approximations for `pow`, `tanh`, `sin`, and `exp`, critical for running on low-power devices like ESP32 and RPi.

## Phase 2: Data-Driven JSON & UI Engine (JUCE HAL)
*ToadTracker's JUCE Desktop/Plugin wrapper (`hal/juce/ToadAudioProcessor`) should leverage our JSON APVTS architecture to eliminate hardcoded UI layouts.*

1. **Migrate `ParameterManager`**:
   - Port `source/ParameterManager.cpp` and `.h` to `ToadTracker/hal/juce/`.
   - Implement the `assets/controls/*.json` pipeline to load UI metadata (colors, tooltips, ranges, labels).
2. **Hook Up APVTS to ToadTracker's Serializer**:
   - Bridge the `juce::AudioProcessorValueTreeState` (generated by the `ParameterManager`) to ToadTracker's core `serializer.cpp` / `ui_state.h`.
3. **Migrate Theme System**:
   - Port `global_ui.json` and the vector-based `LookAndFeel` engine. This gives ToadTracker immediate access to our curated theme palettes (Cykranosh, Dracula, etc.) and high-DPI scaling.

## Phase 3: Testing Parity (Reflection Guardrails)
*ToadTracker already has excellent core testing via Catch2, but its JUCE UI layer needs our automated reflection guardrails.*

1. **Retain Catch2 for Headless Core Tests**:
   - Continue using `Catch2` (`toad_core_tests`) for the `hal/rpi`, `hal/esp32`, and `core` codebases.
2. **Port `gui_tests` to JUCE HAL**:
   - Migrate `test/gui_tests.cpp` and `test/ReflectionGuardrailSuite.h` into `ToadTracker/hal/juce/test/`.
   - Setup the test suite to automatically sweep 100% of the loaded JSON parameters against ToadTracker's APVTS to catch missing parameters, unmapped tooltips, or bounds mismatches.
3. **Screenshot Automation**:
   - Port `capture_screenshot.cpp` to ToadTracker to automate README generation and release snapshots.
